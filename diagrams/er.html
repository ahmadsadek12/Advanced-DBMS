Figure 1. ER Diagram

Movie Ratings (MySQL). Crow’s foot. Composite keys on the two relationship tables.

entity associative entity audit table (triggers)   PK primary key   FK foreign key   UQ unique

Cardinality

  • movies N:M keywords via movie_keywords. 100 keywords is realistic (heist, neo-noir, folk horror). 100 genres would not have been.
  • movies N:M people via movie_people. role is part of the PK because the same person can direct and write the same film.
  • character_name / credit_order belong to the relationship, not to people.
  • users 1:N ratings, movies 1:N ratings. One row per (user, movie).
  • rating_log is 1:N from ratings in practice, but it is not a real FK. Deletes still leave history.

Indexes (chosen for the demo queries)

  • FULLTEXT ft_movies (title, description) — homepage MATCH AGAINST
  • idx_ratings_movie (movie_id), idx_ratings_user (user_id), idx_ratings_rated_at (rated_at)
  • idx_mp_person (person_id), idx_mp_role (role) — filmography / credit lookups. movie_id is already the left column of the PK
  • idx_mk_keyword (keyword_id) — keyword average join. movie_id is already the left column of the PK
  • idx_movies_year, idx_movies_title, idx_log_movie
  • Mongo movie_reviews: movieId, userId, tags
